# Чатики — оболочка Electron

Это не отдельный сайт и не отдельный бэкенд. Приложение открывает уже готовый мессенджер

`https://sco1-vapp-09.sgp.ru/messenger/`

в своём окне и добавляет то, чего нет у обычной вкладки браузера: иконку в трее, системные уведомления, снимок экрана и локальный HTTP-сервер.

## Два слоя в одном процессе

При старте поднимаются две разные вещи.

**Electron** умеет окно, трей, экран и уведомления Windows. Его код лежит в `src/main` и `src/preload`.

**Express** принимает HTTP-запросы на `http://0.0.0.0:3737`. Его код лежит в `src/server`. Сам по себе он не видит экран и не показывает уведомления. При запуске Electron передаёт ему две функции:

- `onNotify` — показать системное уведомление;
- `onScreenshot` — снять основной экран и вернуть PNG в base64.

Так сервер остаётся обычным Node-приложением, а доступ к компьютеру остаётся у Electron.

Страница мессенджера живёт на другом адресе (`*.sgp.ru`). Поэтому у Express включён CORS: страница может звать `localhost:3737`.

## Что происходит при запуске

Точка входа — `src/main/index.js` (поле `"main"` в `package.json`).

1. До создания окна для `*.sgp.ru` включается встроенный вход Windows (Kerberos/NTLM). Флаги задаются и старыми именами `whitelist`, и новыми `allowlist` из Electron 44. После старта то же самое делает `session.allowNTLMCredentialsForDomains`. У окна по-прежнему выключены `webSecurity` и запрет смешанного содержимого — без этого корпоративная страница может не открыться.
2. Открывается окно и в него загружается мессенджер.
3. В трее появляется иконка «Чатики». Крестик окна приложение не закрывает, а прячет. Выход только через меню трея → «Выйти».
4. Регистрируются IPC-каналы для страницы.
5. Вызывается `startServer`: Express слушает порт `3737`.
6. При выходе сервер сначала останавливается, потом процесс завершается.

Общие числа и адреса собраны в `src/config.js`: порт, хост, URL мессенджера, размер окна, маска SSO.

## Папки

```
src/
  config.js            общие настройки
  main/                процесс Electron (Node + доступ к системе)
    index.js           старт и остановка
    window.js          окно браузера
    tray.js            иконка в трее
    ipc.js             команды от страницы
    screenshot.js      захват экрана
    paths.js           пути к assets и preload
    state.js           живые ссылки на окно, трей и сервер
  preload/
    index.js           мост window.electronAPI
  server/              Express
    index.js           слушает порт и умеет остановиться
    createApp.js       json, CORS, подключение маршрутов
    routes.js          /health, /notify, /screenshot
    polyfill.js        crypto, без него MCP SDK не стартует
    mcp/
      index.js         адрес /mcp
      tools/           отдельные инструменты MCP
assets/
  tray-icon.png        иконка трея (если файла нет, берётся заглушка)
  sounds/message.mp3   свой звук; системное уведомление работает и без него
```

`state.js` нужен потому, что сборщик мусора Node уничтожает окно и трей, если на них не осталось ссылки.

## Как страница разговаривает с оболочкой

Страница мессенджера — чужой сайт. Ей нельзя давать `require` и весь Node. Поэтому между ней и Electron стоит preload.

Preload (`src/preload/index.js`) публикует в страницу объект `window.electronAPI`: сделать скриншот, показать окно, проиграть уведомление, получить источники экрана. Внутри это вызовы `ipcRenderer`. Обработчики сидят в `src/main/ipc.js`. Страница видит только эти методы.

## Как устроен Express

`src/server/index.js` только запускает и останавливает сервер.

`createApp.js` собирает приложение: разбор JSON (до 20 МБ, чтобы пролез скриншот), заголовки CORS, маршруты.

Обычные адреса в `routes.js`:

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/health` | жив ли сервер |
| POST | `/notify` | уведомление, тело `{ title, body, count? }`. Без `count` счётчик на значке растёт на 1, с `count` ставится это число |
| POST | `/badge` | только счётчик на значке, тело `{ count }` |
| GET | `/screenshot` | PNG основного экрана в base64 |

MCP — отдельный протокол поверх того же порта, адрес `/mcp`. Инструменты лежат по одному файлу в `src/server/mcp/tools/`:

- `run_command` — только команды из белого списка (`ls`, `pwd`, `whoami` и ещё несколько);
- `send_notification` — то же уведомление, что и `POST /notify`;
- `take_screenshot` — тот же снимок, что и `GET /screenshot`;
- `get_status` — платформа, pid и время.

Режим MCP stateless: каждый `POST /mcp` — отдельный запрос. `GET` и `DELETE /mcp` отвечают 405.

## Один и тот же жест — два входа

Скриншот и уведомление можно вызвать и со страницы, и по HTTP. Оба входа заканчиваются в Electron.

Скриншот со страницы: `electronAPI.takeScreenshot()` → IPC `take-screenshot` → `screenshot.js`. Картинка берётся с учётом масштаба экрана.

Скриншот по сети: `GET /screenshot` или инструмент MCP `take_screenshot` → функция `onScreenshot`, которую передал main.

Уведомление со страницы: `electronAPI.playNotificationSound()`. Точное число непрочитанных: `electronAPI.setBadgeCount(3)`.

Уведомление по сети: `POST /notify` или инструмент `send_notification`. Счётчик на значке трея рисуется в самой иконке, поэтому он виден и в Windows 11, и в трее KDE на Альт Linux. Открытие окна сбрасывает счётчик.

## Запуск и сборка

```bash
npm install
npm start
```

`npm start` открывает окно. Сервер при этом пишет в консоль:

```
[HTTP] REST:  http://0.0.0.0:3737/health
[MCP]  URL:   http://0.0.0.0:3737/mcp
```

Установщик Windows:

```bash
npm run dist
```

Готовые файлы попадают в папку `dist/`.

Сборка RPM для Альт Linux 10 и 11 описана в `README.AltLinux.md`.
